* Installing
  Install Org Everywhere from a =.vsix= (Extensions view, =...= menu, /Install from
  VSIX.../) or build one: =npm install && npx vsce package=. Open any
  =.org= file and it starts.

  Then run *Org: Open A Practice File*, or the walkthrough (/Help > Get
  Started/, then /Get started with Org Everywhere/), which takes you through the
  essentials a step at a time.

  #+CAPTION: The walkthrough: each step ticks itself off as you do it.
  [[./images/walkthrough.png]]

* What works on its own, and what needs the orgs server
  Editing works with nothing else: the outline, TODO keywords, tables (and
  their alignment, sorting and plotting), links, footnotes, completion,
  statistics cookies, the column view, narrowing and the decorations.

  The *orgs server* reads all your org files and does what spans files or
  runs things: the agenda, clocking, refile and archive, table formulas,
  running source blocks, exporting, capture, habits, encryption,
  attachments, history and search. It lives at
  [[https://github.com/ihdavids/orgs][github.com/ihdavids/orgs]], and *Org: Read the orgs Docs* opens its
  manual - the =docs/docs.html= on github's main branch - in a tab beside
  your files (it keeps a copy, for when github cannot be reached).

* A server of your own, set up for you
  *Org: Set Up a Local orgs Server* (also in the status bar's menu, and the
  walkthrough) does the whole thing:

  - downloads the latest orgs release for your machine from github and
    checks it against the release's checksums
  - asks which folder of org files it should read
  - writes it an =orgs.yaml= - http on =localhost:8010=, or the next free
    port - with a login whose password is made at random and kept in VS
    Code's secret storage, so you are never asked for it
  - starts it, points *Org: Orgs Connection* at it and logs in

  It runs in the background, shared by every VS Code window, and keeps
  running when VS Code closes; a window that opens and finds it stopped
  starts it again (=org.orgsServer.autoStart=). Once a day the plugin asks
  github for a newer release and offers it (=org.orgsServer.checkForUpdates=).

  | Command                             | Does                                            |
  |-------------------------------------+-------------------------------------------------|
  | Org: Start/Stop/Restart orgs Server | What they say                                   |
  | Org: Update orgs Server             | Install a newer release, restarting it if it runs |
  | Org: Edit orgs Server Config        | Open its =orgs.yaml=; saving it reloads the server |
  | Org: Show orgs Server Log           | What it printed when it last started            |

  Most of the config takes effect when you save it; a change to the port,
  =orgDirs= or the keystore asks for a restart. Running source blocks is off
  until you add a =babel:= block. The files live in VS Code's global storage
  for the extension (=.../globalStorage/iorg.vscode-org-everywhere/orgs/=).

  It answers on =https://localhost:<port>= and nothing else: no plain http,
  and nothing from another machine. Its certificate is self-signed, made by
  =orgs cert= when it is set up and renewed before it runs out; VS Code
  trusts that certificate for that server and no other. A browser warns
  about it until you trust it - /Trust its certificate in browsers/ in the
  server's menu does that on macOS and windows. A server set up over http
  before this moves to https by itself once its orgs is new enough.

  Nobody has to log in to it:

  - VS Code logs in with the password it keeps, for worg's views as well.
  - The =orgs= there is the command line client too. It reads the
    =orgs.yaml= beside it, which holds the server's keys, so it makes its
    own token and asks for no password. VS Code's terminals have it first
    on =PATH= (=org.orgsServer.addToTerminalPath=). Anywhere else, run it
    by its path or alias it: /Use it from a terminal/ in the server's menu
    (*Org: Set Up a Local orgs Server* again, once it is set up) copies it.
  - *Org: Open worg in Browser*, or =orgs worg [View]= from a terminal,
    opens worg already logged in, through a link that works once, for a
    minute.

  For a login of your own - to type into worg in any browser, or =orgs
  login= on another machine - use *Org: Manage orgs Users* (/Users and
  passwords/ in the same menu). Adding a user works at once. Changing a
  password or removing a user restarts the server for a moment. =vscode= is
  VS Code's own login and is left alone; /Copy its password/ gives you its
  password if you ever need it.

* Connecting to a server you run
  Start it with =orgs serve= in the directory with its =orgs.yaml=, then
  set *Org: Orgs Connection* (=org.orgsConnection=) to the server's address -
  =http://localhost:8010=, or =https://…= for one with a certificate
  (=org.allowSelfSigned= accepts a self-signed one).

  A server that wants a login asks once, and the plugin keeps you logged in.
  A server started with =noAuth: true= wants none: the plugin asks the server
  when it starts (and whenever the address changes) and skips the login.

* The status bar
  In an org file, the left of the status bar says how the server is:

  | Shows                | Means                                              |
  |----------------------+----------------------------------------------------|
  | ☁ orgs               | Connected                                          |
  | 👤 orgs: log in      | The server wants a login                           |
  | ⚠ orgs (highlighted) | The server is not answering                        |

  Click it to log in or out, check again, open worg, change the address, or
  set up (or start, stop and update) a local orgs server.
  It checks again every couple of minutes and when you come back to the
  window. In a table it also shows the cell (=@2$3=) and its formula; on the
  right, the running clock and any timer.

* Using VSCodeVim
  Everything works in insert mode. In normal mode Tab folds headings and
  moves between table cells, and Alt+H/J/K/L move headings, rows and
  columns. *Org: Set Up Vim Table Keys* adds =<leader>t…= mappings for the
  table commands. See [[*Keys][Keys]].
