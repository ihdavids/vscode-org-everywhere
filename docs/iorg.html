Contents

·

    Org Everywhere brings Emacs Org mode to VS Code: outlines that fold with Tab, TODOs and an agenda, tables that align themselves and work out their own formulas, links you follow with F12, a clock, capture, refiling, running code and exporting - and, with the orgs server, all of it across every org file you have.

    Find what you need

    • A key: Keys has the ones worth knowing; Every key binding lists them all, by where they work, with the macOS spelling beside each.
    • A command: Commands lists every one, by subject, with what it does and its key.
    • A setting: Settings.
    • Anything: type in the search box at the top of this page - a key (ctrl+alt+o), a command (refile) or a word (formula). The arrow keys step through what it finds.
    • In VS Code: Ctrl+Alt+O M opens a menu of every org command, with the ones that fit where the cursor is first and each one's key beside it.

    Getting started

    Installing

    Install Org Everywhere from a .vsix (Extensions view, ... menu, Install from VSIX…) or build one: npm install && npx vsce package. Open any .org file and it starts.

    Then run Org: Open A Practice File, or the walkthrough (Help > Get Started, then Get started with Org Everywhere), which takes you through the essentials a step at a time.

    What works on its own, and what needs the orgs server

    Editing works with nothing else: the outline, TODO keywords, tables (and their alignment, sorting and plotting), links, footnotes, completion, statistics cookies, the column view, narrowing and the decorations.

    The orgs server reads all your org files and does what spans files or runs things: the agenda, clocking, refile and archive, table formulas, running source blocks, exporting, capture, habits, encryption, attachments, history and search. It lives at github.com/ihdavids/orgs; start it with orgs serve in the directory with its orgs.yaml.

    Connecting

    Set Org: Orgs Connection (org.orgsConnection) to the server's address - http://localhost:8010, or https://… for one with a certificate (org.allowSelfSigned accepts a self-signed one).

    A server that wants a login asks once, and the plugin keeps you logged in. A server started with noAuth: true wants none: the plugin asks the server when it starts (and whenever the address changes) and skips the login.

    The status bar

    In an org file, the left of the status bar says how the server is:

    Shows Means
    ☁ orgs Connected
    👤 orgs: log in The server wants a login
    ⚠ orgs (highlighted) The server is not answering

    Click it to log in or out, check again, open worg, or change the address. It checks again every couple of minutes and when you come back to the window. In a table it also shows the cell (@2$3) and its formula; on the right, the running clock and any timer.

    The outline

    Headings are the shape of an org file. These keys work on the heading the cursor is on; they only take over on a heading line, so elsewhere Tab and Alt+Up do what they always do.

    Showing and hiding

    Key Does
    Tab On a heading: folded, then its children, then everything under it
    Shift+Tab On a heading: the whole file - top headings, then every heading, then all

    Drawers (:PROPERTIES:, :LOGBOOK:) stay folded as you open things up, as org keeps them. VS Code's own folding keys work too (and za, zc, zo in vim).

    Moving and reshaping

    Key Does
    Alt+Up / Alt+Down Move the subtree past the heading before or after it
    Alt+Shift+Left / Alt+Shift+Right Promote or demote the subtree
    Alt+Left / Alt+Right Cycle the TODO keyword, or step a date under the cursor

    A subtree moves with everything under it; blank lines stay where they were in the layout, so the spacing between entries does not change.

    Sorting

    Sort (Ctrl+Alt+O O) sorts whatever the cursor is in:

    • on or under a heading: the headings under it - alphabetically, by TODO state (in your keyword order), by priority, by scheduled or deadline date, or numerically. The text above the first child stays put.
    • in a list: its items, with the lines under each, alphabetically, numerically, or checked/unchecked first. A numbered list is numbered again.
    • in a table: its rows by the cursor's column (see Tables).

    With vim

    In normal mode Tab and Shift+Tab cycle as above, and on a heading:

    Key Does
    Alt+K / Alt+J Move the subtree up / down
    Alt+H / Alt+L Promote / demote the subtree

    Narrowing

    Narrow To Subtree (Ctrl+Alt+O Shift+N) opens the subtree the cursor is in in a tab of its own - org's C-x n s. It is an org document like any other: tables, links and completion all work. Saving it writes the subtree back into its file and saves the file; changes made to the file show up in it. Close the tab to widen. (Commands that go through the orgs server - refile, clock, run - work from the whole file.)

    Statistics cookies

    Put [/] or [%] on a heading and it keeps count: [2/5], [40%]. It counts the keywords of the headings directly under it (how many are done), or, with none of those, the checkboxes in its own entry. It updates as you change a keyword or tick a box, in the same undo step. org.autoStatistics turns it off; Update Statistics Cookies does it by hand.

    Tables

    Type a table the way you would write one by hand and press Tab: it is aligned and the cursor moves on.

|-                    ===>       |-------+-----+-------|
|apple|3|1.50                    | apple |   3 |  1.50 |

    Columns that are mostly numbers line up on the right, as org has them. Link markup that the editor hides does not count towards a column's width.

    Alignment and width cookies

    A row of cookies sets how each column sits and how wide it shows:

    | <c>  | <r> | <12>                              |
| Name | Age | Notes                             |

    <l>, <r> and <c> align a column. <N> shows the column N characters wide: what does not fit is hidden and ends in an ellipsis, until the cursor is in the cell. <r8> does both.

    Formulas

    Formulas live on the #+TBLFM: line under the table and are worked out by the orgs server. Recalculating sends the table as it reads in the editor - unsaved changes too - and puts the answer back, so it is one undo and needs no save.

    Key Does
    Ctrl+Alt+O R Recalculate the table
    Ctrl+Alt+O Shift+R Recalculate every table in the file
    Ctrl+Alt+O = Edit the formula for the cell under the cursor
    • With the cursor in a cell, the status bar shows the cell's reference (@3$2) and the formula that fills it; hovering shows it too. The cells that formula writes are outlined.
    • Type $1*2 after an = in a cell ($1*2) and press Tab: it becomes a formula for the whole column. =:= makes one for that cell alone.
    • highlight($3, "red"), red($3), green($3) … and gradient($2, $2, "red", "yellow", "green") colour the cells they fill after a recalculation. The colours go when the table is next changed.
    • org.tableAutoRecalc: "marked" (the default) recalculates when Tab or Enter leaves a row with # in its first column, as org does; "always" on every Tab and Enter; "off" only when asked.
    • org.tableRecalcOnSave recalculates every table when the file is saved.

    Recalculating needs a reachable orgs server you are logged in to.

    Making tables

    • Create Table: a header, a rule and empty rows, sized as you ask.
    • Convert Selection To Table: the selection, or the paragraph the cursor is in, split on tabs, commas, semicolons or runs of spaces. A first row of words over rows of numbers gets a rule under it.
    • Paste As Table and Import CSV As Table do the same with the clipboard or a file.

    Finding tables

    • Go To Table lists every table the orgs server knows, with its name, heading, size and formula count (this file's tables without a server).
    • Insert Table Name inserts a #+NAME: for remote(name, @2$3).

    Sorting, turning, adding up

    • Sort Table Rows (Ctrl+Alt+O O) sorts the rows between the rules around the cursor by its column: alphabetical, numeric or by date, either way. The likely one is offered first.
    • Transpose Table turns rows into columns.
    • Sum Table Column adds up the column (or the selected rows of it) and copies the total. Times like 1:30 add up as times.

    Plotting

    Plot Table (Ctrl+Alt+O G) opens a chart beside the editor that follows the table as you edit it. Without anything else, the first column of words is the x axis and the columns of numbers are the series: words give bars, numbers and dates give lines, and times plot as hours. An org-plot line above the table says otherwise:

    #+PLOT: title:"Sales" ind:1 deps:(2 3) with:histograms

    with:lines, points and histograms pick lines, dots and bars. The chart has a table view and saves as svg.

    Shift+F12 (gr in vim) On a heading: every link to it, from every org file

    What links point at

    Link Goes to
    [[*Heading]] The heading with that title in this file
    [[#custom-id]] The heading with that :CUSTOM_ID:
    [[id:5f2c…]] The heading with that :ID:, in any file
    [[file:notes.org]] Another file
    [[file:notes.org::*Heading]] A heading in another file (also ::#id, ::42 for a line)
    [[target]] A <<target>>, else a heading of that name, else the text
    [[https://…]], mailto: Opened outside VS Code
    [[./pics/cat.png]] An image: hover to see it

    An id: that is not in the workspace is asked of the orgs server.

    Making links

    Insert Link offers every heading in the workspace - this file's first - plus "a web address…" and "a file…". Type to find a heading anywhere. It links by :ID: when the heading has one, by :CUSTOM_ID: next, by title otherwise, and asks for a description (empty for none). With text selected, that text is the description.

    Store Link remembers the heading you are under; Insert Link then offers it first, from any file, with the right relative path. The link also goes on the clipboard.

    Typing [[ offers the headings, custom ids and targets of this file and the workspace's other org files (see Completion).

    For a link that survives the heading being renamed or moved, give it an ID first: Insert ID (see Dates and properties).

    Completion

    Suggestions come up as you type, from this file first, then the workspace, then the orgs server (every tag and property it knows) when you are logged in.

    Where you type You are offered
    after the stars of a heading TODO keywords - yours, and the file's #+TODO:
    after a : at the end of a heading Tags, the ones used most first; pick one and the next is offered
    #+ at the start of a line Keywords; BEGIN_SRC, BEGIN_QUOTE… come with their #+END
    after #+BEGIN_SRC Languages, the ones this file uses first
    : in a :PROPERTIES: drawer Property names
    after :NAME: in a drawer That property's values, from everywhere
    after [[ Headings, custom ids and targets, and other org files

    Lower case #+begin_src gives lower case keywords.

    Column view

    Column View (Ctrl+Alt+O Shift+C) shows the file's headings as rows and their keyword, priority, properties and tags as columns, beside the editor - and you can edit any cell.

    • The columns are the file's #+COLUMNS: line's:

      #+COLUMNS: %40ITEM %TODO %PRIORITY %EFFORT(Estimate){:} %OWNER %TAGS

      Without one: heading, state, priority, effort, the properties the file uses most, and tags.

    • A column summed with {:} (times like 1:30) or {+} (numbers) shows each heading the total of the headings under it, in grey where the heading has no value of its own. Effort is summed by default.
    • Tab moves between cells; Enter (or leaving the cell) keeps a change, Escape puts it back. State and priority are lists to pick from. Emptying a property cell takes the property out.
    • The › beside a heading goes to it.

    Edits go straight into the document - one undo each, no server needed - and the view follows the org file you are in.

    Running code

    One key runs whatever the cursor is on: Ctrl+Alt+O R.

    Turning it on

    Running source blocks is off on a new orgs server, because a source block is a program. Turn it on, for the languages you want, in its yaml:

    babel:
  enable: true
  languages: ["python", "sh"]

    Until then Run says so, rather than failing quietly. Dynamic blocks and tables need nothing turned on.

    Capture

    Capture has as its primary goal of getting it out of your mind now. When you capture you are grabbing a concept and quickly putting it in your inbox for later refiling. Orgs and vscode make this possible through a hybrid approach. Orgs does the capture operation while vscode handles the text input.

    The orgs server allows you to define capture targets in its configuration file. These are synced with your vscode settings file automatically. Your vscode settings file then allows you to extend these capture targets with a snippet template to use when filling out one of these captures. These snippets use the normal vscode snippet rules:

    As an example, variables should work just fine: VsCode Snippet Rules

    Capture targets are stored in the selector section of your vscode capture definition.

        "todo": {
        "type":     "entry",
        "snippet":  "* ${1:HEADING}\n  [$CURRENT_YEAR $CURRENT_MONTH $CURRENT_DATE $CURRENT_HOUR:$CURRENT_MINUTE]\n   ${2:BODY}",
        "selector": "orgs_capture_target_name",
    },

    Orgs will automatically create entries for all targets is has defined in your settings. This can get in the way if you don't want them but do not want to regenerate them. To fix that use the hide: true field to remove it as an active option for captures in your vscode settings.

    Quick capture

    Ctrl+Alt+O Q, from anywhere in VS Code: pick a capture template (the one you used last comes first), type one line, Enter. It is filed by the orgs server and you carry on where you were - no capture page opens. Use the full capture (Org: Capture) when you want a body, tags or a snippet.

    Capture Targets

    Capture targets specify where the new entry should go. They are used for captures, refiles and archiving. Captures targets come in a variety of types.

    TARGET TYPES

    • file "path/to/file" - Text will be placed at the beginning or end of that file.
    • id "id of existing org entry" - Filing as child of this entry, or in the body of the entry.
    • customid "customid of existing org entry" - Filing as child of this entry, or in the body of the entry.
    • file+headline "filename" "node headline" - Fast configuration if the target heading is unique in the file.
    • file+olp "filename" "Level 1 heading" "Level 2" … - For non-unique headings, the full path is safer.
    • file+regexp "filename" "regexp to find location" - Use a regular expression to position point.
    • file+datetree "filename" root - This target creates a root datetree for today’s date.
    • file+olp+datetree "filename" [ "Level 1 heading" …] - This target creates a heading in a date tree for today’s date. If the optional outline path is given, the tree will be built under the node it is pointing to, instead of at top level. Check out the :time-prompt and :tree-type properties below for additional options.
    • clock - insert at position of active clock
    • hash dynamically assigned hash - during a run of the server nodes are dynamically assigned a hash

    Capture Types

    Capture come in a variety of types. Types define the type of org mode component you are inserting. The simplest is entry in that your are capturing a full heading and body.

    • entry - This is a subnode of whatever the target it pointing at.
    • plain - This is plain text added somewhere in the node.
    • item - this is a list item added to the end of a list in the target.
    • checkitem - this is a checkbox list item added to the end of a checklist in the target (or end of target)
    • table-line - This is a line of a table added to whatever table is in the document

    Refile

    Many organization methodologies have the concept of an inbox and one or more triage stages of the process. Org supports these notions through capture and refile. Once captured you can then, later, place the information where you need it by refiling it. Refiling simply moves the data to a more appropriate location.

    The org.refile command will refile the subtree under your cursor to a target of your choosing. Refile targets are determined in one of several ways:

    The global option in the orgs configuration file determines the generic search path. This is a list of org files. Here we are searching every org file in our entire org setup for refile targets:

     "refileTargets": [".*\\.org"]

    Archive

    Some methodologies make use of the concept of a reference. There are numerous ways of handling a reference. Refiling can be made to support reference material. The other is the use of an archive. Org has 2 ways that you can archive files:

    • Placing an ACHIVE tag on a heading or filetags. This removes it from consideration for the agenda amoung other things.

    • Moving the heading from the current file to a refile target. Refile targets are determined programmatically through the use of an #+ARHIVE: comment. This is a filename and heading combination:

      #+ARCHIVE: %s_done::* My Heading

    This will move from the current file to <currentfile>.org_done under a * My Heading parent heading.

    When the filename is omitted, archiving happens in the same file. %s in the filename will be replaced by the current file name (without the directory part). Archiving to a different file is useful to keep archived entries from contributing to the Org-mode Agenda.

    The archived entries will be filed as subtrees of the specified headline. When the headline is omitted, the subtrees are simply filed away at the end of the file, as top-level entries. Also in the heading you can use %s to represent the file name, this can be useful when using the same archive for a number of different files.

    The default archive behaviour is as follows and can be configured in the Org Yaml file as follows

    "archiveDefault": "%s_archive::"

    New Archive File

    If a new archive file is created it will use a template for generating the archive file:

    "newFileTemplate": "newfile.tpl"

    You can configure this to have the file headings you would like in your archive file.

    Archive Properties

    Archiving will automatically add some standard properties to a heading as it is archived:

    file from where the entry came, its outline path the archiving time org-archive-save-context-info Parts of context info that should be stored as properties when archiving. When a subtree is moved to an archive file, it loses information given by context, like inherited tags, the category, and possibly also the TODO state (depending on the variable `org-archive-mark-done'). This variable can be a list of any of the following symbols:

    • time The time of archiving.
    • file The file where the entry originates.
    • ltags The local tags, in the headline of the subtree.
    • itags The tags the subtree inherits from further up the hierarchy.
    • todo The pre-archive TODO state.
    • category The category, taken from file name or #+CATEGORY lines.
    • olpath The outline path to the item. These are all headlines above the current item, separated by /, like a file path.

    For each symbol present in the list, a property will be created in the archived entry, with a prefix \"ARCHIVE_\", to remember this information."

    "archiveSaveContextInfo": ["time", "file"]

    If true empty properties in the ArchiveSaveContextInfo are not included in the archive output, false all listed properties will be included even if empty.

    "archiveSkipEmptyProperties": true

    Developers

    How the plugin is put together, for anybody changing it. The sections after this one are written in the code itself, beside what they describe, as SDOC comment blocks.

    Building, testing, and this manual

    npm install
npm run compile      # TypeScript into out/
npm run lint         # ESLint
npm run test:unit    # the model tests, in node
npm test             # and the extension tests, in a VS Code
tools/docs/build.sh  # this manual: docs/iorg.org and docs/iorg.html
tools/docs/build.sh --screenshots   # ...taking the screenshots again

    The manual is built with docex from the orgs repository (expected beside this one, at ../orgs, or wherever ORGS_DIR says). It reads three things:

    • the guides in docs/guide/ - each names its place with #+DOC_ORDER: (and #+DOC_SECTION: to sit inside another);

    • SDOC blocks in the TypeScript sources, written like this, which file under Developers:

      /* SDOC: Developers
* The tables model
  What it is for...
EDOC */
    • the key, command and setting references, which tools/docs/reference.js writes from package.json and tools/docs/command-notes.json (one line about each command - add one when you add a command).

    The screenshots are taken by tools/docs/screenshots.js: it opens VS Code on a demo workspace (tools/docs/demo/) with an orgs server behind it, plays the scenes in tools/docs/scenes.js, and captures each through the Chrome DevTools Protocol.

    The shape of the code

    The newer code keeps each feature's logic in a model with no vscode in it, tested in plain node, under a thin layer that talks to the editor:

    Model Editor side
    src/tables/model.ts src/tables/commands.ts, view.ts, calc.ts, plot.ts
    src/tables/formulas.ts (formula targets, for the highlight and the editor)
    src/outline/model.ts src/outline/commands.ts, refile.ts, stats.ts
    src/links/model.ts src/links/providers.ts
    src/decorations-scan.ts src/decorations.ts
    src/columns-model.ts src/columns.ts
    src/footnotes-model.ts src/footnotes.ts
    src/lines.ts src/edit-lines.ts (one minimal edit per change)

    Everything that needs the orgs server goes through src/db.ts (ODb); src/auth.ts logs in, or notices a server that needs no login.

    Decorations

    The pretty-printing - link markup hidden, a heading's stars shown as one bullet, headings styled, source blocks shaded - is drawn from one pass over the lines (decorations-scan.ts scanLines), a moment after typing stops (OrgExtension.update). Each decoration type is made once, in the constructor, and disposed with the extension; nothing is created per update.

    Links in the editor

    Following a link is VS Code's Go to Definition (LinkDefinitions), backlinks are its Find References (Backlinks), so F12, Shift+F12 and vim's gd / gr work with nothing bound. resolve turns a target into a place: this file for *heading, #custom-id and <<target>>; the file for file: links and their :: searches; the workspace, then the orgs server (GET /id/), for id:. ClickableLinks makes them Ctrl+clickable through a command: uri; LinkHover previews images and headings.

    Logging in, or not

    Auth holds the token from a login and refreshes it before it runs out. probe() asks the server, with no token, whether it answers: open (a noAuth: true server - no login needed), closed, or unreachable. isLoggedIn() is true for a valid token or an open server, so everything that waits for a login works against a noAuth server; onAccessChanged tells the status bar (connection.ts).

    Narrowing

    org-narrow: is a small file system (NarrowFs): reading a narrowed uri gives the subtree's lines from its source document, found by the heading line it started at (or, if that moved, by its text); writing replaces those lines with a WorkspaceEdit and saves the source. Changes to the source fire a change event for its narrowed views, so they reload.

    Previews

    One panel per kind (web, reveal, impress, gantt, mind map), filled from the server's exporters (ODb.exportText). The page gets a small script first (SHIM): acquireVsCodeApi once (pages from the server may ask for it again), the scroll position kept in the webview state across redraws, and s to save. Redrawn on save, not on a timer.

    Recalculating tables

    Formulas are worked out by the orgs server, but from the editor's text: calculate sends the table and its #+TBLFM: lines to POST /table/calc, which writes nothing and answers with the table as it reads afterwards (and any colours highlight() and friends gave cells). The answer is put back as one edit, so a recalculation is one undo and needs no save; if the document changed while the server was thinking, the answer is dropped.

    Colours are kept per document against the formatted text of the table they belong to; a table that no longer reads that way has lost them.

    The outline model

    Headings, subtrees and the edits on them, as plain functions over an array of lines: parseHeading (keyword, priority, title, tags), headingAt, subtreeEnd, children, moveSubtree, sortChildren, sortList, setProperty / removeProperty, setHeadingParts, cycleKeyword, updateCookies, findOlp / olpOf. Each edit returns the block of lines it rewrites, which replaceLines puts back with a minimal edit.

    Keywords are passed in: fileKeywords reads a file's own #+TODO: line, and COMMON_KEYWORDS is used where neither the file nor the settings are to hand.

    The table model

    OrgTable is a table as rows of cells (a rule is a row with no cells), parsed from lines with OrgTable.parse and written back aligned with format(measure). Every table command is: find the table (tables/editor.ts tableAt), change the model, write it back - which goes through diffLines, so only what changed is touched and it is one undo.

    • Alignment follows org: a column that is more than half numbers (isNumber, org's number pattern plus currency and thousands separators) is right-aligned; a cookie row (<l>, <r>, <c>, <N>) overrides that, and <N> is shown N wide by tables/view.ts.
    • measure is how wide a cell looks: measureWith(prettyLinks) counts a link as its description, and wide east asian characters as two.
    • The cursor is placed by cellTextStart and found by cellIndexAt, which read the line as it is - so a table typed by hand, not yet aligned, works.

    Waiting for the server's writes

    Many commands ask the orgs server to change a file (refile, archive, clock, run a block). VS Code notices the change on disk in its own time. settled(files) waits until every open, unmodified copy of those files reads as the disk does, so the next command - or keystroke - sees the new text. Commands that make the server write call it before they return.

    readLines reads a file for looking across files: the editor's copy if it is open (unsaved changes and all), the disk otherwise, cached on mtime.

    Writing back with minimal edits

    replaceLines(editor, start, end, lines) rewrites a block of a document with the single smallest edit (diffLines in lines.ts): common lines and the common start and end of a changed line are left alone. That keeps undo to one step, and leaves the cursor, markers and VSCodeVim's idea of where things are undisturbed wherever nothing moved - writing a whole table back used to move the cursor twice and confuse vim.
